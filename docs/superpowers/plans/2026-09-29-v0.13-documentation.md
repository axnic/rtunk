# v0.13 — Documentation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **Every writing task in this plan is MANDATORY for the `tech-doc-writer` agent** (per the project owner's global CLAUDE.md agent rules) — no task may be drafted by any other agent type.

**Goal:** Ship every document `ROADMAP.md`'s `v0.13` milestone requires, so `v1.0` can follow with "precise, exhaustive documentation" as its only remaining gate.

**Architecture:** Two passes. Pass A audits and brings the existing internal notes (`docs/architecture/*.md`, `docs/cli.md`) up to date against the current code, since two milestones (internal/cli reorg, pkg/git extraction, ignore/shellcheck additions) shipped since they were last touched. **Tech Stack:** Markdown, Mermaid (already used in `docs/architecture/README.md`), the repo's own `rtunk`/`trunk` dogfood lint stack (`markdownlint`, `prettier`) as the verification tool for every file this plan touches.

**Spec:** [ROADMAP.md](../../../ROADMAP.md) — `## v0.13 — Documentation` section (the thirteen-document list, each with its own Purpose/Audience/Done-when) is this plan's literal spec; every task below quotes its own slice of it. ## Global Constraints

- License is **MIT** (user decision, 2026-09-29) — copyright line uses git user `Alexandre NICOLAIE`.
- Zero telemetry / no cloud account / no daemon / no self-upgrade — carry these `AGENTS.md` "permanently out of scope" and "non-negotiable design rules" items into README/CONTRIBUTING/installation accurately; never imply a feature that AGENTS.md forbids.
- rtunk has **no packaged release yet** — no `.goreleaser.yml`, no `Makefile`, `--version` reports `dev`. The installation guide documents building from source (`go install` / `mise`), not downloading a prebuilt binary; do not invent a release artifact that does not exist.
- Doc style per `CLAUDE.local.md`: dense, precise prose, `##`/`###` headers, no marketing language, no emoji. Package/reference docs cite sources inline `(path, path:line)`.
- Every command, flag, and config key documented must be verified against the actual built binary (`./rtunk help --all`, `./rtunk <cmd> --help`) or the actual source (`pkg/trunk/config`, `pkg/ignore`), never against `docs/cli.md`'s prose alone — that file is itself being audited in Task 1 and may contain stale internal-file-path narration not meant for a public audience.
- Commit convention: `.agents/skills/git-commit/SKILL.md` — every commit in this plan is `@[docs]: Subject` (type `@` Docs, scope `docs`), signed (`git commit -S`), with an `Assisted-by: anthropic:claude-sonnet-5` trailer, never `Co-authored-by:` inside the body (the session's own attribution trailer for the *outer* commit wrapping this work, if the user asks for one at the end, follows the system reminder's format instead — that is a session-level concern, not this plan's).
- `rtunk`'s own dogfood lint stack (markdownlint, prettier via `.trunk/trunk.yaml`) is the verification tool for every file this plan creates or edits — run `./rtunk fmt <paths>` then `./rtunk check <paths>` before every commit, not a manual read-through alone.

## Review Focus

- **A reader with zero prior context lands on the bare repo root.** No README today — someone arriving from a search engine or a GitHub link sees `AGENTS.md`/`ROADMAP.md` first, which are agent-oriented, not a landing page. Task 8 (README) is reviewed against: can a stranger tell what rtunk *is* and how to run their first check from this file alone, per the roadmap's own Done-when.
- **A documented command/flag that doesn't actually exist, or one that exists but isn't documented.** The single highest-cost failure mode for a "public, authoritative" reference: Task 2 must diff its own draft against `./rtunk help --all` output and every subcommand's `--help`, not just docs/cli.md prose.
- **A configuration key rtunk actually reads that the reference omits, or a documented key that isn't read.** Task 3 must be checked against `pkg/trunk/config`'s actual struct/tag definitions (grep the package), not just prior docs.
- **LICENSE/CODE_OF_CONDUCT/SECURITY copied from a template with the wrong project name, wrong contact, or a placeholder bracket left unfilled.** These are the documents least likely to get a careful read once merged (boilerplate fatigue) and the ones where a leftover `[INSERT EMAIL]` is most embarrassing publicly. Task 7's own step explicitly greps the three files for `[`/`TODO`/`INSERT` after drafting.
- **The migration guide promising trunk-compatibility rtunk doesn't have, or omitting a divergence trunk users will actually hit.** Task 6 must be built from `AGENTS.md`'s "Deliberate divergences from trunk" list and `docs/architecture/inconsistencies.md` — an exhaustive cross-check, not a summary from memory of the codebase.
