# v0.10 Fix Commands and Finding Autofixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement ROADMAP.md v0.10's fix/formatter/autofix bullets: a fix-only linter (in-place,
not a formatter) is now selectable and runnable; a finding that already carries a computer-applied
fix from its own linter is applied, not just reported; `check --fix` means linter fixes only
(fix commands + finding-level autofixes); a new `--format-before-check` flag reproduces today's
`--fix` (formatter-then-check) behavior, opt-in instead of implicit.

**Architecture:** No engine execution changes are needed for the fix-command half: a fix command is
already `InPlace: true, Formatter: false`, and `pkg/trunk/engine`'s change-detection (`hashFiles`,
`ChangedFiles`) is already keyed on `InPlace` alone, not `Formatter` — it already works for any
in-place command once `engine.Run` is given a predicate that selects one. The only new engine-side
work is the predicate itself and one new field (`Command.Platforms` already showed this pattern in
the previous plan). The finding-level-autofix half is new: `output.Finding` gains an optional inline
`Fix` payload, decoded from ESLint's own `messages[].fix` (the one real, currently-parsed format
that carries it), and a new pure function applies non-overlapping fixes directly to file content.
`internal/cli/check.go`'s `Run` is restructured around two checking passes when `--fix` is given:
pass 1 finds issues, fix commands and finding-level fixes are applied to the files pass 1 flagged,
pass 2 reports whatever remains.

**Tech Stack:** Go, testify (`require`/`assert`), existing `pkg/trunk/output`/`pkg/trunk/engine`
machinery.

**Spec:** [ROADMAP.md](../../../ROADMAP.md) v0.10, bullets "Fix-only linters actually fix.",
"Findings apply their own attached fix.", "`check --fix` means linter fixes only.", and
"`--format-before-check` recreates the previous combined behavior.";
[docs/architecture/inconsistencies.md](../../architecture/inconsistencies.md) entries #1, #2, #4.
Real catalog field names verified directly against github.com/trunk-io/plugins: `fix_prompt`/
`fix_verb` on a command (`linters/dart/plugin.yaml`'s `fix` command — `in_place: true`, no
`formatter`, `enabled: false` by default — the exact non-formatter-fix shape entry #1 describes);
ESLint's own `--format json` messages carry a `fix: {range: [start, end], text}` object per
autofixable message (ESLint's documented formatter output, confirmed against a real `messages[]`
entry), which `pkg/trunk/output/eslint.go`'s current decode struct has no field for.

## Global Constraints

- Exit codes stay `0`/`1` only (AGENTS.md, "Exit codes").
- `fmt` writes to the working tree only, never the index (AGENTS.md) — unaffected by this plan
  (fmt's own formatter-only selection is untouched); `check --fix` is the same in-place-write
  contract, extended to fix commands and finding-level fixes.
- No new dependency.
- **Overlapping finding-level fixes in the same file**: apply every fix whose byte range doesn't
  overlap one already applied (highest-offset-first, so earlier offsets stay valid); a fix that
  overlaps one already applied in the same pass is left untouched, its finding unresolved this
  pass, and reachable by running `--fix` again after the file's already-applied fixes have landed
  (the same fixed-point-over-repeated-runs shape ESLint's own native `--fix` has). Confirmed with
  the user during planning — the alternative (skip the whole file when any two fixes in it
  overlap) was declined.

## Review Focus

- **A fix command that fails (non-`error_codes` exit, or an `error_codes` exit)** must not abort
  `check --fix`'s pass 2 — matches this project's existing per-linter failure isolation (one
  linter's `Failed` event has never stopped its siblings, and `--format-before-check`'s own
  pre-existing pass already tolerates a `Failed` event the same way). Pinned in Task 4.
- **`--fix` with no findings in pass 1** must run no fix command and apply no inline fix — nothing
  to fix, and firing every enabled fix command over every file regardless of findings would defeat
  "applied to what the checking pass found." Pinned in Task 4.
- **A finding with a `Fix` payload whose command is not itself a `Formatter`** (the ESLint case)
  must be applied even when the linter declares no separate fix command at all — the two mechanisms
  (entry #1's fix commands, entry #2's finding-level fixes) are independent and both apply under
  plain `check --fix`, neither gated on the other existing. Pinned in Task 4.
- **`--format-before-check` and `--fix` given together** must run the format pass, then pass 1,
  then fix application, then pass 2 — each stage sees the previous stage's writes, matching how
  `--fix`'s own pre-existing formatter pass already fed the (single) checking pass that followed
  it. Pinned in Task 4.
- **A `Fix` payload whose `Range` is invalid for the file's current content** (stale — the file
  changed since the tool produced the finding, e.g. two linters both touched it) must not corrupt
  the file or panic; skipped for that file/fix, same as an overlap. Pinned in Task 2.

```go
package engine

import (
	"os"
	"sort"

	"github.com/xunleii/rtunk/pkg/trunk/output"
)

// ApplyInlineFixes writes every non-overlapping output.Finding.Fix in findings to disk, grouped by
// File. Within one file, fixes are applied highest-Range-first so an earlier replacement's byte
// offsets stay valid for the next; a fix whose Range overlaps one already applied in this file, or
// whose Range no longer fits the file's current content (stale -- the file changed since the tool
// produced it), is left untouched: its Finding is unresolved this pass, and a repeated `check
// --fix` picks it up once the conflicting fix has landed and pass 1 re-reports it (the same
// fixed-point-over-repeated-runs shape a tool's own native --fix has). Returns the absolute paths
// actually rewritten, deduplicated and sorted.
func ApplyInlineFixes(findings []output.Finding) ([]string, error) {
	byFile := map[string][]*output.InlineFix{}
	for i := range findings {
		if findings[i].Fix == nil {
			continue
		}
		byFile[findings[i].File] = append(byFile[findings[i].File], findings[i].Fix)
	}

	var changed []string
	for file, fixes := range byFile {
		content, err := os.ReadFile(file)
		if err != nil {
			return changed, err
		}
		sort.Slice(fixes, func(i, j int) bool { return fixes[i].Range[0] > fixes[j].Range[0] })

		out := content
		applied := false
		appliedFrom := len(content) + 1 // nothing applied yet -- any range is "before" this
		for _, fix := range fixes {
			start, end := fix.Range[0], fix.Range[1]
			if start < 0 || end > len(content) || start > end || end > appliedFrom {
				continue // out of bounds, or overlaps a fix already applied (higher offset)
			}
			out = append(out[:start:start], append([]byte(fix.Text), out[end:]...)...)
			appliedFrom = start
			applied = true
		}
		if !applied {
			continue
		}
		if err := os.WriteFile(file, out, 0o644); err != nil {
			return changed, err
		}
		changed = append(changed, file)
	}
	sort.Strings(changed)
	return changed, nil
}
```

```go
// findingFiles returns the deduplicated, sorted set of files findings reports on -- check --fix's
// own fix-command pass and inline-fix pass only ever touch what pass 1 actually flagged.
func findingFiles(findings []output.Finding) []string {
	seen := map[string]bool{}
	var out []string
	for _, f := range findings {
		if !seen[f.File] {
			seen[f.File] = true
			out = append(out, f.File)
		}
	}
	sort.Strings(out)
	return out
}

// runFixCommands runs every enabled fix command (in-place, not a formatter -- ROADMAP.md v0.10
// "Fix-only linters actually fix") over files, reusing engine.Run's existing InPlace
// change-detection (already keyed on InPlace alone, not Formatter). A fix command's own Failed
// event is recorded (via printFn, check --fix's shared renderer) but does not itself abort --
// matches --format-before-check's own pre-existing tolerance of a Failed formatter.
func runFixCommands(ctx context.Context, env engine.Env, files []string, printFn func(engine.Event)) (changed, skipped []string, failed error) {
	events, err := engine.Run(ctx, env, files, func(cmd config.Command) bool { return cmd.InPlace && !cmd.Formatter })
	if err != nil {
		return nil, nil, err
	}
	_, changed, skipped, failed = drainRunEvents(printFn, events)
	return changed, skipped, failed
}
```
