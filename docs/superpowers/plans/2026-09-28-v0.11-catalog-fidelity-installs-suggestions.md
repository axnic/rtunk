# v0.11 catalog fidelity — installs/suggestions

## Context

ROADMAP.md v0.11 lists 17 items closing the gap between what the real trunk plugin catalog
declares and what rtunk's engine actually consults (`docs/architecture/inconsistencies.md`'s
"Declared-but-inert catalog fields"). Two prior plans already landed:
`2026-09-27-v0.11-cache-consolidation.md`, `2026-09-27-v0.11-shared-provisioning.md`, and
`2026-09-27-v0.11-catalog-fidelity-execution.md` (run_timeout, prepare_run, max_concurrency,
disable_upstream — all merged to main). This plan covers the remaining 4 execution-adjacent
items, grouped because all 4 live in the installs/suggestions surface rather than the per-command
run path Group 3 already covered:

- **Suggested linters** (`suggest_if`, linter-level, **129** catalog occurrences — the single most
  common inert field in the whole catalog).
- **Security findings are tagged** (`is_security`, command-level, 22 occurrences).
- **Tool installs verified** (`health_checks`, tool-level, 20 occurrences).
- **Companion packages install automatically** (`extra_packages`, tool-level, 6 occurrences).

Per `docs/architecture/plugin-model.md`'s field table: `suggest_if` is "parsed, never consulted"
(the field already exists as `config.Linter.SuggestIf`, unused); the other 3 are "not modeled,
dropped while parsing" (no struct field exists yet). None of the 4 has a confirmed real-catalog
example of every declared shape's edge case in this repo's own fixtures beyond what's cited per
task below — each task's own Design note says exactly what's confirmed vs. inferred.

Real trunk-catalog occurrence counts and field-shape descriptions are from
`docs/architecture/plugin-model.md`'s survey table and `docs/architecture/inconsistencies.md`'s
"Declared-but-inert catalog fields" section — read both before starting if anything below is
unclear about a field's intended behavior.

## Global Constraints

- Go 1.x, this repo's existing conventions (`gofmt`, `go vet`, table-driven tests, no new external
  dependencies).
- Every new YAML field gets `omitempty` and a doc comment matching this codebase's existing style
  (state the real catalog example if one exists in `pkg/trunk/config/testdata/`, note the intended
  behavior, and any deliberate scope limit).
- **Reproducibility** (AGENTS.md): "Linters, runtimes, and tools are version-pinned in config and
  installed hermetically per that pin. There is no silent fallback to whatever happens to already
  be on PATH." Every task below that installs or invokes something new must honor this — no
  unpinned installs, no assuming latest.
- No task adds a new CLI flag unless its own section says so explicitly — the bar is "the declared
  field's documented intended behavior actually happens," not a new user-facing surface beyond
  that.
- Run `go build ./... && go vet ./... && go test ./... -race` after every task; every existing test
  must keep passing unchanged (regressions are load-bearing findings, not "expected changes").
- Ignore gopls/IDE "not included in your workspace" diagnostics inside a worktree under
  `.worktrees/` — known stale noise from this project's git-worktree-based SDD workflow, not real
  errors. Trust `go build`/`go vet`/`go test` as ground truth.

## Review Focus

- **Task 1 (suggest_if):** an unset `SuggestIf` must behave EXACTLY as today (files-matched ⇒
  Available) — this is an existing, tested behavior with real users depending on it; don't
  silently change the default. `never` must remove a files-matching linter from Available (moves
  it to Other), not merely fail to add it. `config_present` must check `DirectConfigs` file
  presence, not `Files` pattern matching — confirm the two are genuinely decoupled in the new code
  (a `config_present` linter with zero matching `Files` but a present config must still surface).
- **Task 2 (is_security):** every one of the ~13 real output parsers in `pkg/trunk/output/` builds
  its own `Finding{}` literals independently (pass_fail, regex, sarif, actionlint, bandit,
  buildifier, cfn_lint, eslint, hadolint, hamllint, markdownlint, pylint, rubocop, stylelint,
  taplo) — tagging `IsSecurity` per-parser would mean touching 13 files and risking missing one.
  Confirm the task instead uses the SAME post-parse pattern `ApplyIssueURL` already uses (one call
  site per real invocation path, not per parser) — this is the whole point of that design, verify
  it's actually followed.
- **Task 3 (health_checks):** `buildJobs`/`resolveShimDirs` run serially in the engine's own setup
  goroutine, one linter at a time, strictly BEFORE the worker pool starts — confirm the
  implementation does NOT add unnecessary synchronization (no `sync.Once`/mutex needed here, unlike
  Group 3's prepare_run/max_concurrency, which really do run concurrently inside the worker pool).
  Confirm a tool referenced by two different linters only has its health check run ONCE per
  `engine.Run` call, not once per linter.
- **Task 4 (extra_packages):** the landmine this task exists to avoid: `install.Finalize` is a bare
  `os.Rename(tmpDir, destDir)` — calling any runtime's install function a SECOND time against an
  ALREADY-FINALIZED `pkgInstallDir` silently no-ops (the rename fails because destDir exists, then
  the fallback treats "destDir already exists" as "a concurrent caller already finished," and
  discards the second call's tmpDir entirely without installing anything or returning an error).
  Confirm the fix is "install main + every extra package into ONE shared tmpDir, one Finalize call
  at the end" — not "call the existing single-package function N times into the same destDir."
  Confirm every one of the 6 runtime installers (`go.go`, `node.go`, `php.go`, `python.go`,
  `ruby.go`, `rust.go`) was updated, not just a subset, and that each extra package entry without
  an explicit `@version` pin is rejected (Reproducibility), not silently installed unpinned.

```go
func buildLintersList(cfg config.Config, repoRoot string, files []string) listing {
	pinned := enabledVersions(cfg.Lint.Enabled)
	configPresent := directConfigFiles(repoRoot, files) // see Step 4

	names := make([]string, 0, len(cfg.Lint.Definitions))
	for name := range cfg.Lint.Definitions {
		names = append(names, name)
	}
	sort.Strings(names)

	l := listing{Enabled: []listItem{}, Available: []listItem{}, Other: []listItem{}}
	for _, name := range names {
		linter := cfg.Lint.Definitions[name]
		n := 0
		for _, f := range files {
			if engine.Matches(cfg, linter, f) {
				n++
			}
		}
		item := listItem{ID: name, Files: &n, Description: linter.Description, label: countLabel(n, linter.Files)}
		if version, ok := pinned[name]; ok {
			item.Version = version
			l.Enabled = append(l.Enabled, item)
			continue
		}
		if suggested(linter, n, configPresent) {
			l.Available = append(l.Available, item)
		} else {
			l.Other = append(l.Other, item)
		}
	}
	return l
}

// suggested applies suggest_if's real 3 values (files_present, config_present, never) to decide
// whether a not-yet-enabled linter belongs in the Available (suggested) bucket. Unset SuggestIf
// keeps this project's own pre-existing default (files_present's own behavior: n > 0), for every
// linter that doesn't declare the field.
func suggested(linter config.Linter, n int, configPresent bool) bool {
	switch linter.SuggestIf {
	case "never":
		return false
	case "config_present":
		return configPresent
	default: // "files_present", or unset -- today's own pre-existing default
		return n > 0
	}
}
```

```go
// directConfigFiles reports whether any of linter's own DirectConfigs paths (repoRoot-relative,

func directConfigFiles(repoRoot string, files []string) map[string]bool {
	present := map[string]bool{}
```

**Interfaces:**
- Produces: `config.Tool.HealthChecks []string` (new, `yaml:"health_checks,omitempty"`) — each
  entry a `Run`-shaped invocation template string (same convention `Command.PrepareRun` already
  established: exit-code-only, no output parsing; unlike `PrepareRun`, a health check has no
  `${plugin}`/`${cwd}` context, since a `Tool` has no plugin-source directory of its own — only a
  `Linter`/`Action` does).
- Produces: `resolveShimDirs` and `buildJobs` both gain a `ctx context.Context` parameter (new —
  neither has one today) and a `healthChecked map[string]error` parameter (built once in `Run`,
  passed down, read-and-written serially — see Design note).

**Design note (read before starting):** `buildJobs` is called once per linter from `Run`'s own
setup goroutine (`engine.go` around line 245, inside `go func() { ... }()`), strictly BEFORE the
worker-pool loop starts (`engine.go` around line 304's `for i := 0; i < concurrency; i++`) — every
call to `buildJobs`/`resolveShimDirs` for every linter happens serially, one at a time, in a single
goroutine. This is a genuinely different concurrency shape from Group 3's `prepare_run`/
`max_concurrency` (which run concurrently inside the worker pool and needed `sync.Once`+stored-
error / a semaphore): here, a plain `map[string]error` — no mutex, no `sync.Once` — is enough to
cache "already ran this tool's health check, here's what happened" across the serial calls for
different linters that happen to share a tool. Confirmed real trunk-io shape is unconfirmed in this
repo's own fixtures; `HealthChecks []string` mirrors `PrepareRun`'s own established string-list,
exit-code-only design for the same category of "declared setup/verification invocation" field.

```go
func resolveShimDirs(ctx context.Context, cfg config.Config, root, cacheDir, repoRoot string, toolIDs []string, failed map[string]error, healthChecked map[string]error, emit func(Event), log *runlog.Writer) ([]string, error) {
	dirs := make([]string, 0, len(toolIDs))
	for _, id := range toolIDs {
		tool, ok := cfg.Tools[id]
		if !ok {
			return nil, fmt.Errorf("engine: tool %q referenced but not found in resolved config", id)
		}
		version := download.ResolveVersion(cfg.Lint.Enabled, id, tool.KnownGoodVersion)
		shimPath := download.ShimPath(root, "tools", id, version, id)
		if err := failed["tools/"+id]; err != nil {
			return nil, err // already attempted (and reported) by prefetch
		}
		if _, statErr := os.Stat(shimPath); statErr != nil {
			evs, err := download.Download(cfg, cacheDir, repoRoot, download.Ref{Category: "tools", ID: id, Version: version})
			if err != nil {
				return nil, err
			}
			if err := forwardInstall(evs, emit); err != nil {
				return nil, err
			}
		}
		download.Touch(root, "tools", id, version)

		if len(tool.HealthChecks) > 0 {
			if err, checked := healthChecked[id]; checked {
				if err != nil {
					return nil, err
				}
			} else {
				shimDir := filepath.Dir(shimPath)
				err := runToolHealthChecks(ctx, tool, id, shimDir, repoRoot, log)
				healthChecked[id] = err
				if err != nil {
					return nil, err
				}
			}
		}

		dirs = append(dirs, filepath.Dir(shimPath))
	}
	return dirs, nil
}

// runToolHealthChecks runs every one of tool's declared HealthChecks (exit-code-only, no output
// parsing -- see Tool.HealthChecks's own doc comment), using shimDir as the PATH prefix so the
// check invokes the tool this install just resolved, not whatever else might be on PATH. A tool
// has no plugin-source directory of its own (unlike a Linter/Action), so pluginDir/cwdDir are
// empty and repoRoot is used as the invocation's own working directory.
func runToolHealthChecks(ctx context.Context, tool config.Tool, toolID, shimDir, repoRoot string, log *runlog.Writer) error {
	for _, check := range tool.HealthChecks {
		checkCmd := config.Command{Name: "health_check", Run: check}
		id := log.NextID()
		inv := runlog.Event{T: runlog.KindInvocation, ID: id, Linter: toolID, Sandbox: ""}
		_, stderrOut, exitCode, err := runOneInvocation(ctx, checkCmd, repoRoot, shimDir, nil, "", "", log, inv, "")
		if err != nil {
			return err
		}
		if exitCode != 0 {
			msg := strings.TrimSpace(stderrOut)
			return fmt.Errorf("engine: tool %q: health check failed (exit %d): %s", toolID, exitCode, msg)
		}
	}
	return nil
}
```

**Interfaces:**
- Produces: `config.Tool.ExtraPackages []string` (new, `yaml:"extra_packages,omitempty"`) — each
  entry `"<name>@<version>"` (mandatory version pin, no unpinned form — see Design note; the `@`
  split mirrors this project's own existing `enabled: [id@version]` convention, e.g.
  `internal/cli/list.go`'s `cutVersion`, though that helper itself lives in `internal/cli` and
  should not be imported into `pkg/trunk/download` — a local `strings.Cut(entry, "@")` is enough).
- Produces: `runtime.PackageSpec{Name, Version string}` — one companion package to install
  alongside a runtime package's own main `pkg@version`.
- Changes: `runtime.Runtime.Install`'s field type gains an `extra []PackageSpec` parameter (every
  one of the 6 `installXPackage` functions assigned to it, and its one caller `download.
  InstallPackage`, change together).

**Design note (the reason this is its own task, not a one-line change):** `install.Finalize`
(`pkg/trunk/install/`) is a bare `os.Rename(tmpDir, destDir)`; if `destDir` already exists (which
it will, the moment the tool's own main package has already been installed there), the rename
fails and the fallback path treats "destDir already exists" as "a concurrent caller already
finished successfully" and silently discards `tmpDir` — meaning calling any existing
`installXPackage` function a SECOND time against the SAME `pkgInstallDir` (naively, once per extra
package) would silently no-op every extra package, reporting success while installing nothing.
Extra packages must genuinely land in the SAME install tree as the tool's own main package (that's
the entire point — e.g. an eslint plugin package must be importable from the exact same
`node_modules` eslint itself resolves against) — a separate directory per extra package would be
implementable but practically useless. The correct fix: every one of the 6 runtime installers
builds ONE shared `tmpDir`, runs its ecosystem's own install command once per package (main +
every extra) all targeting that SAME `tmpDir`, and calls `install.Finalize` exactly ONCE at the
very end. Per AGENTS.md's Reproducibility principle ("no silent fallback to whatever happens to
already be on PATH... version-pinned"), an `ExtraPackages` entry with no `@version` is a config
error (reject it, don't guess a version or install unpinned) — this project has no other precedent
for an unpinned tool/runtime/package install anywhere.

```go
func installPythonPackage(runtimeInstallDir, pkgInstallDir, pkg, version string, extra []PackageSpec) error {
	pip := filepath.Join(runtimeInstallDir, "bin", "pip")
	if _, err := os.Stat(pip); err != nil {
		return fmt.Errorf("runtime: pip not found at %s: %w", pip, err)
	}
	if err := os.MkdirAll(filepath.Dir(pkgInstallDir), 0o750); err != nil {
		return err
	}
	tmpDir, err := os.MkdirTemp(filepath.Dir(pkgInstallDir), ".tmp-*")
	if err != nil {
		return err
	}
	defer func() { _ = os.RemoveAll(tmpDir) }()

	env := append(os.Environ(),
		"PATH="+filepath.Join(runtimeInstallDir, "bin")+string(os.PathListSeparator)+os.Getenv("PATH"),
		"PIP_CONFIG_FILE="+os.DevNull, "PYTHONHOME=", "PYTHONPATH=", "PIP_TARGET=", "PIP_USER=",
	)
	install_ := func(name, ver string) error {
		cmd := exec.Command(pip, "install", "--prefix", tmpDir, name+"=="+ver)
		cmd.Env = env
		out, err := cmd.CombinedOutput()
		if err != nil {
			return fmt.Errorf("runtime: pip install %s==%s: %w: %s", name, ver, err, out)
		}
		return nil
	}
	if err := install_(pkg, version); err != nil {
		return err
	}
	for _, e := range extra {
		if err := install_(e.Name, e.Version); err != nil {
			return err
		}
	}
	return install.Finalize(tmpDir, pkgInstallDir)
}
```

(`install_` is a local closure purely to avoid repeating the same 6 lines twice in this one
