# v0.12 — Renovate integration, promoted to a public command

## Context

ROADMAP.md's v0.12 milestone (the last one before this plan closes out both v0.11 and v0.12,
letting `current_version` advance): Renovate annotation support already exists and works
(`rtunk toolbox renovate enable|disable|config`, added under ROADMAP's earlier "v1.1"/renovate
plan — see `docs/superpowers/plans/2026-09-17-renovate-annotations.md`). This milestone graduates
it from an internal, hidden command surface to a fully documented, first-class part of rtunk's
everyday command set, and proves the generated Renovate snippet actually works against a real
Renovate run, not just a plausible-looking regex nobody ever executed.

Two ROADMAP items:
- **Renovate commands are visible by default.** They currently live under `rtunk toolbox`
  (`internal/cli/cli.go:63`'s `hidden:""` tag), alongside genuinely internal commands (`download`,
  `exec`, `where`) that should stay hidden.
- **The generated Renovate snippet is verified end to end.** Proven against a REAL `npx renovate`
  run, not eyeballed.

**Both ROADMAP items were de-risked before this plan was written** — every unknown below (Kong's
grouping/hidden mechanics, the exact real Renovate CLI invocation that works, which of Renovate's
own config options are repo-level vs. global-only, which `--dry-run` mode avoids a real
platform=local limitation) was directly probed and confirmed working in this session, not
inferred. Task 2's own steps are the literal, verified recipe, not a guess.

## Global Constraints

- Go 1.x, this repo's existing conventions (`gofmt`, `go vet`, table-driven tests).
- Task 2's Renovate verification requires: network access (real GitHub API calls), a GitHub token
  with at least read access (unauthenticated calls hit "GitHub token is required for some
  dependencies" — confirmed directly), and downloading the real `renovate` npm package via `npx`
  (a few hundred MB, cached by npm after the first run). None of this belongs in `go test ./...`
  or CI's default fast suite — it's a real external dependency with real latency and a real
  network/token requirement that would make the whole suite flaky and slow for everyone. Task 2
  is a standalone script, run manually, not wired into `go test`.
- Run `go build ./... && go vet ./... && go test ./... -race` after Task 1; every existing test
  must keep passing (a regression here is load-bearing, not "expected change").
- Ignore gopls/IDE "not included in your workspace" diagnostics inside a worktree under
  `.worktrees/` — known stale noise from this project's git-worktree-based SDD workflow.

## Task 2: Verify the generated Renovate snippet end to end, against a real Renovate run

**Files:**
- Add: `scripts/verify-renovate-e2e.sh` (new, not wired into `go test` or CI — see Global
  Constraints)
- Modify: `docs/cli.md` (a short note on how/why to run the script, and its last real result)

**Interfaces:**
- Produces: a standalone, manually-run shell script that (a) builds rtunk, (b) uses rtunk's OWN
  CLI to produce the real Renovate config snippet and a real annotated sample config, (c) runs the
  real `renovate` CLI (via `npx`) against a scratch repo containing both, and (d) greps its output
  for concrete evidence that a real dependency update was found and would be proposed.

**Design note — the exact recipe below was run and confirmed working in this session's own
research; it is not a guess:**

```bash
$ npx --yes renovate --version
# ... npm deprecation warnings (harmless, from renovate's own transitive deps) ...
42.99.0
```

A scratch repo with `.rtunk/rtunk.yaml` containing (this plan's research hand-wrote this fixture
to validate the mechanism; Task 2 itself must instead get this text from rtunk's OWN `renovate
enable` command against a real fixture linter — see Step 3 below):
```yaml
lint:
  enabled:
    # renovate: datasource=github-releases depName=koalaman/shellcheck
    - shellcheck@v0.7.0
```
and a `renovate.json5` containing ONLY the `regexManagers` block (this plan's research confirmed
`platform`/`onboarding`/`requireConfig` are GLOBAL-only options that Renovate rejects with a
config warning if placed in the repo's own config file -- they must be passed as CLI flags/env
vars instead, not in the file):
```json5
{
  "regexManagers": [ /* the exact snippet `rtunk renovate config` prints */ ]
}
```

Run (this plan's research confirmed `--dry-run=lookup`, NOT `=full` -- `=full` additionally
attempts to simulate writing the update branch, which hits a real, confirmed, platform=local-
specific Renovate limitation, "Cannot sync git when platform=local", unrelated to anything rtunk
controls; `lookup` stops right after finding the update, which is all this task needs to prove):

```bash
GITHUB_COM_TOKEN="<a real GitHub token>" \
RENOVATE_ONBOARDING=false RENOVATE_REQUIRE_CONFIG=ignored LOG_LEVEL=debug \
npx --yes renovate --platform=local --dry-run=lookup
```

Confirmed real output (this plan's research captured this directly, using the hand-written
fixture above -- Task 2 must reproduce the equivalent using rtunk's own real command output):

```
DEBUG: Package releases lookups complete (repository=local)
...
DEBUG: 1 flattened updates found: koalaman/shellcheck (repository=local)
...
"depName": "koalaman/shellcheck",
"currentValue": "v0.7.0",
"datasource": "github-releases",
"replaceString": "# renovate: datasource=github-releases depName=koalaman/shellcheck\n    - shellcheck@v0.7.0",
"updates": [
  {
    "bucket": "non-major",
    "newVersion": "v0.11.0",
    "newValue": "v0.11.0",
    ...
  }
]
```

This is the exact "correctly proposes an update for at least one version-pinned entry" proof
ROADMAP.md's "Done when" line asks for. `koalaman/shellcheck` is a stable choice for this fixture:
a long-lived, high-release-count public repo (old tags never disappear from GitHub), so pinning at
an old real tag reliably finds a newer one indefinitely -- not flaky-by-design the way a
just-released or single-tag repo would be.

- [ ] **Step 1: Write the script's structure**

`scripts/verify-renovate-e2e.sh` (bash, `set -euo pipefail`), roughly:
1. `cd` to a fresh temp dir (`mktemp -d`), clean it up on exit (`trap ... EXIT`).
2. `git init`, `git config user.email/user.name` (a throwaway identity, this repo is never
   pushed anywhere).
3. Build rtunk from this repo (`go build -o "$tmp/rtunk" ./cmd/rtunk`, from the real repo root the
   script itself lives under -- resolve via `git rev-parse --show-toplevel` or
   `dirname "$0"`/.., don't hardcode an absolute path).

- [ ] **Step 2: Get the real config snippet from rtunk's own CLI**

```bash
"$tmp/rtunk" renovate config > "$scratchrepo/renovate.json5.snippet"
```
Wrap it in the outer `{"regexManagers": [...]}` shape it already IS (per the current
`renovateConfigSnippet` constant, `rtunk renovate config`'s whole output is already the complete,
directly-usable JSON5 document -- confirm this against the real current code before assuming it,
the plan's own earlier research read this constant but Task 2 should re-confirm against Task 1's
post-rename command). Write it as-is to `$scratchrepo/renovate.json5`.

- [ ] **Step 3: Get a real annotated fixture from rtunk's own CLI**

Rather than hand-writing the annotated YAML (this plan's own research did that only to validate
the MECHANISM, not as this task's real fixture), build a minimal real `.rtunk/rtunk.yaml` this
task controls (a `plugins.sources` entry pointing at a tiny local/fixture plugin source declaring
one linter backed by a real, stable, long-lived public tool -- `koalaman/shellcheck` again is a
reasonable, already-validated choice, or reuse whatever this repo's own test fixtures already
declare for a tool with a `known_good_version` and a resolvable `renovate.ForLint`/`ForRuntime`
GitHub-releases datasource -- read `pkg/trunk/config/testdata/` and `pkg/trunk/renovate/
annotate.go`'s own resolution rules first to pick a fixture that will genuinely resolve), pin it
at a deliberately OLD real version, then run:

```bash
"$tmp/rtunk" renovate enable --config "$scratchrepo/.rtunk/rtunk.yaml"
```

and confirm (`grep`) the resulting file now contains a real `# renovate: datasource=... depName=...`
annotation this task didn't hand-type -- this is what makes the verification genuinely end-to-end
(rtunk's own annotate step feeds rtunk's own config-snippet step feeds a real Renovate run),
rather than three independently-plausible pieces that were never actually connected.

- [ ] **Step 4: Run the real Renovate CLI against it**

```bash
: "${GITHUB_COM_TOKEN:?set GITHUB_COM_TOKEN (a real GitHub token; e.g. \$(gh auth token) if the gh CLI is already authenticated) before running this script}"
cd "$scratchrepo"
git add -A && git commit -q -m "scratch fixture"
output=$(RENOVATE_ONBOARDING=false RENOVATE_REQUIRE_CONFIG=ignored LOG_LEVEL=debug \
  npx --yes renovate --platform=local --dry-run=lookup 2>&1)
```

- [ ] **Step 5: Assert the proof, print a clear pass/fail**

Grep `$output` for evidence a real update was found for the fixture's own dep name (e.g.
`"updates":` appearing in the JSON debug log alongside the fixture's own `depName`) -- fail loudly
with the captured output on stdout if not found, so a future run's failure is diagnosable, not
just a silent script exit code.

- [ ] **Step 6: Run it for real, capture the evidence**

Actually run `scripts/verify-renovate-e2e.sh` (needs `GITHUB_COM_TOKEN` set -- `gh auth token` if
`gh` is already authenticated in this environment, confirmed available in this plan's own
research) and capture its real pass output.

- [ ] **Step 7: Document it**

Add a short note to `docs/cli.md`'s "## Renovate" section: how to run
`scripts/verify-renovate-e2e.sh` (needs `GITHUB_COM_TOKEN`, network access, and `npx`), why it's a
manual script and not part of `go test ./...` (see this plan's Global Constraints), and the real
result captured in Step 6 (e.g. "last verified <date>: found `koalaman/shellcheck` v0.7.0 → a
real newer release" -- whatever the actual fixture and result end up being).

- [ ] **Step 8: Commit**

