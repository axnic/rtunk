# v0.10 File Selection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement ROADMAP.md v0.10's two file-selection items — the default no-upstream selection
widens to "everything since the last commit," and a path-less invocation outside a git repository
becomes a hard error instead of a silent no-op.

**Architecture:** Both changes live in `internal/cli/selection.go`'s `selectFiles`, the function
behind the no-path default for `check`/`fmt`. The no-upstream branch is unified with the
upstream branch (diff against `HEAD` directly, dropping the separate "staged only" special case);
the outside-git branch returns a new sentinel error instead of an empty, error-free result.
`resolvePaths` and its two callers (`check.go`, `fmt.go`) already turn any non-`errNoFiles` error
from `selectFiles` into the CLI's normal non-zero-exit failure path with no code changes required —
verified by tracing `Run` in `internal/cli/cli.go`, which returns a command's error straight through
to the process's exit code.

**Tech Stack:** Go, testify (`require`/`assert`), `os/exec` shelling out to `git` (existing
`gitOut`/`inGit` helpers).

**Spec:** [ROADMAP.md](../../../ROADMAP.md) v0.10, bullets "Default file selection matches
'everything since the last commit'" and "Running outside git without paths is a hard error";
[docs/architecture/inconsistencies.md](../../architecture/inconsistencies.md) entries #19 and #20.

## Global Constraints

- Exit codes stay `0`/`1` only (AGENTS.md, "Exit codes").
- `selectFiles` never selects a deleted file (existing invariant — `--diff-filter=d`).
- Every path `selectFiles`/`expandPaths` returns is absolute (existing invariant — `absAll`).
- `fmt` writes to the working tree only, never the index (AGENTS.md) — unaffected by this plan, but
  no task here may change what `fmt` writes, only which files are *selected*.
- `--from <ref>` is CI-only diff-base override; explicit paths bypass file selection entirely
  (`expandPaths`, unaffected by this plan).

## Review Focus

- **Explicit paths given outside git** (`rtunk check .` outside a git repo) must still work exactly
  as today (`expandPaths`'s passthrough) — the new hard error is for *no paths* outside git only,
  never for explicit paths. Pinned in Task 2.
- **In git, no upstream, nothing changed at all** (clean working tree, nothing staged/unstaged/
  untracked) must remain the ordinary empty selection (`errNoFiles`, exit 0, "no files to
  check"/"format" message) — this must never be conflated with the new "outside git" hard error.
  Pinned in Task 1 (empty-selection case already covered by existing `TestSelectFiles_*` shape) and
  re-confirmed in Task 2's CLI-level test, which exercises both cases side by side.
- **A file with both staged and unstaged changes** must still appear in the widened no-upstream
  selection (it differs from `HEAD` either way) and must still be caught by `fmt`'s
  `skipPartiallyStaged` skip-with-warning, not silently formatted. Pinned in Task 1.
- **A deleted-but-uncommitted file** must stay excluded from the no-upstream selection now that it
  shares the upstream branch's diff logic (previously only the upstream branch had a test for this
  invariant). Pinned in Task 1.
- **The existing CLI-level test asserting today's exit-0 "outside git, no paths" behavior**
  (`TestCheckFmt_NoPathsOutsideGit_RunsNothing`) must be updated in the same task as the behavior
  change, or the test suite breaks on this task alone. Pinned in Task 2.

Replace `selectFiles` in `internal/cli/selection.go` (lines 67-94) with:

```go
// selectFiles is the no-path file selection: the diff from the diff base (from, else the branch's
// upstream, else HEAD) to the working tree, plus untracked non-ignored files. With an explicit
// base or an upstream, the diff base is merge-base(base, HEAD); with neither, it is HEAD directly,
// so the no-upstream case picks up every staged and unstaged change since the last commit, not
// staged changes only. Outside git, nothing (no timestamp fallback). Deleted files are never
// selected. Paths are absolute.
func selectFiles(repoRoot, from string) ([]string, error) {
	if !inGit(repoRoot) {
		return nil, nil
	}
	base := from
	if base == "" {
		if up, err := gitOut(repoRoot, "rev-parse", "--abbrev-ref", "@{upstream}"); err == nil && len(up) == 1 {
			base = up[0]
		}
	}
	diffBase := "HEAD"
	if base != "" {
		mb, err := gitOut(repoRoot, "merge-base", base, "HEAD")
		if err != nil || len(mb) != 1 {
			return nil, fmt.Errorf("cannot resolve diff base %q: %v", base, err)
		}
		diffBase = mb[0]
	}
	changed, err := gitOut(repoRoot, "diff", "--relative", "--name-only", "--diff-filter=d", diffBase)
	if err != nil {
		return nil, err
	}
	untracked, err := gitOut(repoRoot, "ls-files", "-o", "--exclude-standard")
	if err != nil {
		return nil, err
	}
	return absAll(repoRoot, append(changed, untracked...)), nil
}
```

This collapses the old "staged-only" special case into the same diff-based logic the upstream
branch already used, just measured against `HEAD` instead of a merge-base when there is no
upstream/`--from`.
