# v0.9.3 TTY Live View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On an interactive terminal, `check` and `fmt` draw a live area on stderr (header bar, per-linter tree, install rows) that is erased before the unchanged stdout report; everywhere else the v0.9.1 progress lines are byte-identical.

**Architecture:** 3a adds additive engine events (`Planned`, `JobDone`, `InstallStart|Progress|Done`); 3b adds a `render.NewLive` decorator over any renderer, built from a pure `liveState.frame(...)`, a thin ANSI `screen`, a stdlib `syscall` size query, and CLI wiring (`--ascii`, `--live-height`).

**Tech Stack:** Go stdlib (`syscall`, `os/signal`, `time`), testify. No new dependency.

**Spec:** `docs/superpowers/specs/2026-09-26-v0.9.3-tty-live-view-design.md` (exact layouts, algorithms, emission points, test list: the spec sections are the brief for every task below; this plan orders the work and pins the interfaces).

## Global Constraints

- No new dependency (no `golang.org/x/term`, no bubbletea); terminal size via stdlib `syscall` TIOCGWINSZ in a `//go:build unix` file, 80x24 fallback elsewhere.
- Engine changes are additive: new `Phase` values appended after `Failed`; every existing consumer ignores them (`base.Event`, `drainRunEvents`, `collectChangedByLinter`, `logLinterEnd`).
- Live view only when stderr is a terminal, `--no-progress` is off and `TERM != "dumb"`; otherwise the v0.9.1 plain progress lines, byte-identical, no `\x1b` on stderr.
- The live area is drawn on stderr and erased before `inner.Close`; stdout content, exit codes, run logs unchanged. The cursor is never hidden.
- Braille bar: 7 glyph states per cell (`⣀ ⣄ ⣤ ⣦ ⣶ ⣷ ⣿`), 6 sub-steps; spinners `Dots` 80 ms / `Sand` 70 ms from docs/ux.md; lines capped at `width-1` runes.
- Commits follow `.agents/skills/git-commit/SKILL.md` via the `git-commit-assistant` agent (body must not start with a lowercase word, lines <= 80 chars), ending with `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>`.

## Review Focus

- A goroutine or ticker left running after `Close` (writes after Close would corrupt the report). Pinned in Task 4.
- A `Failed` install for a tool whose runtime failed first must not produce an unbalanced `InstallDone`. Pinned in Task 1.
- `check --fix` (two live renderers in sequence) and `fmt --verify-stable` (re-plan per round): the second area must start clean and the bar must not exceed 100%. Pinned in Tasks 3 and 5.
- A frame wider or taller than the terminal (auto-wrap would break the cursor-up arithmetic). Pinned in Task 3.
- Ctrl+C mid-run leaves no live area behind and the process still exits as interrupted. Pinned in Task 4 (handler logic testable through an injectable signal channel).
