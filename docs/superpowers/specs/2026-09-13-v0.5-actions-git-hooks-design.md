# v0.5 — Actions & Git Hooks: Design

**Status:** self-ruled (user asleep; explicit standing authorization to decide by comparison
against real trunk-io behavior — see Rulings section).

## Goal

Implement ROADMAP.md's v0.5 milestone in full:

- `rtunk actions run` — run a specified action on demand, or every action a given git hook fires.
- `rtunk actions history` — see recent runs of an action.
- `rtunk actions list` — list all actions available for the current configuration.
- `rtunk actions enable` / `rtunk actions disable` — toggle actions in `trunk.yaml`.
- `rtunk git-hooks install` / `rtunk git-hooks uninstall` — manage the git hook shims that trigger
  actions automatically.

`config.Action` (`pkg/trunk/config/definitions.go`) already exists as parsed-but-unused data:
`ID`, `DisplayName`, `Description`, `Runtime`, `PackagesFile`, `Run`, `Triggers` ([]Trigger, each
`GitHooks`/`Files`/`Schedule`), `Interactive`, `NotifyOnError`. `Config.Actions` is already a
`CategoryConfig[Action]` with `Enabled`/`Definitions`, already trimmed by `filterEnabled`, already
validated by `Validate`. `download.fetchActionRef` already resolves an action's `Runtime` (but not
`PackagesFile`). Nothing executes an action's `Run` string yet, and nothing installs a git hook.

## Non-goals (ruled, grounded in AGENTS.md + real catalog inspection)

- **`schedule:` and `files:` triggers do not auto-fire.** Real trunk-io fires these from its own
  daemon (a background process watching a clock/filesystem). AGENTS.md permanently forbids "the
  trunk daemon." `Trigger.Schedule`/`Trigger.Files` remain parseable (already are) but are inert in
  v0.5: only `git_hooks` triggers wire to anything, and `rtunk actions run <id>` still runs a
  schedule/files-triggered action manually. This is a real, disclosed capability gap versus trunk,
  not an oversight.
- **`PackagesFile` support is node-only.** The real trunk-io/plugins catalog has exactly one
  action using it (`actions/commitlint/plugin.yaml`, `packages_file: package.json`, `runtime:
node`). `download.InstallPackage` already dispatches per-runtime-type for named-package installs
  (node/python/go/ruby/rust/php) and explicitly errors for unimplemented types rather than
  guessing; `InstallPackagesFile` (new) follows the same pattern — node implemented, everything
  else an explicit "not yet supported" error.
- **No per-action-definition "default enabled" concept.** This repo's own `.trunk/trunk.yaml`
  currently has `actions: {disabled: [trunk-announce], enabled: [commitlint, ...]}` — `disabled:`
  was added by the user's own real `trunk` CLI when `trunk-announce` (never in `enabled:`) was
  turned off. No real `actions/*/plugin.yaml` in the cached catalog carries any
  enabled-by-default-style field. Simplest model consistent with the evidence: `enabled:` is the
  sole source of truth for what runs (unchanged, already implemented by `filterEnabled`);
  `disabled:` is a symmetric, purely-advisory sibling list that `rtunk actions enable/disable`
  keep in sync (mirroring what real `trunk`'s own CLI just did to this repo's file), with zero
  effect on resolution. This is a ruling, not a confirmed trunk internal — cheap to revisit if
  wrong, costs nothing today since nothing reads `Disabled` except the enable/disable commands
  themselves.
- **Desktop notifications are best-effort, not a feature surface.** `notify_on_error: true` (the
  implied default — every real example that sets it explicitly sets it to `false`, to suppress)
  fires a native notification (macOS `osascript`, Linux `notify-send` if present, silent no-op
  elsewhere/on any error) when the action's `run` exits non-zero. No configuration, no queue, no
  retry — a single best-effort `exec.Command`, error ignored.
- **`interactive: true` skips in a non-interactive context; `optional` and unset always run.**
  Grounded directly in the real catalog: `trunk-check-pre-push` (`interactive: true`) and
  `trunk-check-pre-push-always` (`interactive: optional`, "will always run, even in non-interactive
  contexts" — the plugin.yaml's own comment) are two variants of the _same_ action differing only
  in this field, which only makes sense if `true` is the one that gets skipped. "Non-interactive
  context" = `os.Stdin` is not a character device (`stat` mode check), the standard Go idiom.

## Config layer changes (`pkg/trunk/config`)

1. **`Action.Environment []EnvironmentEntry`** (new field, `yaml:"environment,omitempty"`) — real
   catalog example: `actions/git/plugin.yaml`'s `git-lfs` action passes `SSH_AUTH_SOCK`/
   `SSH_AGENT_PID`/`GITHUB_SERVER_URL` through this way. Reuses the existing `EnvironmentEntry`
   type (already used by `Runtime.RuntimeEnvironment`/`LinterEnvironment`). Resolved the same way
   `download.BuildEnv` already resolves those — see the actions package below.
2. **`Action.SourceDir`/`Action.SourceRoot`** (new fields, both `yaml:"-"`, mirroring
   `Linter.SourceDir`/`SourceRoot` exactly) — an action's `run:`/`Environment` can reference
   `${cwd}` (resolved relative to `${plugin}`), e.g. `git-blame-ignore-revs`' `run: bash
${cwd}/update_config.sh`. `parseSourceDir` (resolve.go) already stamps `SourceDir` onto every
   `Lint.Definitions[i]` it reads from a `plugin.yaml` match; extend the same loop to also stamp
   `Actions.Definitions[i]`. `setSourceRoot` already stamps `SourceRoot` onto every `Lint`
   definition from a source's root dir; extend it to do the same for `Actions`.
3. **`CategoryConfig[T].Disabled []string`** (new field on the shared generic, `yaml:",omitempty"`
   via the inline embed) — parses `trunk.yaml`'s `actions.disabled:` list (see Non-goals above for
   why it has no resolution-time effect). Only `trunkFile.Actions` gains a `Disabled []string
yaml:"disabled"` field feeding it; `Lint`/`Runtimes` are untouched (out of scope — this repo's
   real file has never used `lint.disabled`/`runtimes.disabled`, and extending those categories
   isn't part of v0.5's bullets).
4. **`cacheSchemaVersion` bump** (`cache.go`, currently 3 → 4): `Action.Environment` is a new field
   an already-cached git plugin source's JSON would silently decode as `nil` — the exact same class
   of bug hit three times already this session (`ParseRegex`, `SourceDir`, `Download.Args`). Bump
   pre-emptively rather than wait to hit it in production a fourth time.
5. **`Validate`** already runs `checkEnabled("action", ...)` against `Enabled`; no change needed
   for `Disabled` (advisory only, nothing to validate against).

## `pkg/trunk/download` addition: `InstallPackagesFile`

New file `runtime_node.go` gains (or a new function beside `installNodePackage`):

```go
// InstallPackagesFile installs every dependency named in the manifest at packagesFilePath through
// rt's own package manager into pkgInstallDir. Unlike InstallPackage (a single pkg@version),
// there is no version to key the install on -- pkgInstallDir's caller is responsible for choosing
// a stable location (see actions.installDir below: content hash of the manifest).
func InstallPackagesFile(rt config.Runtime, runtimeInstallDir, pkgInstallDir, packagesFilePath string) error {
	switch rt.Type {
	case "node":
		return installNodePackagesFile(runtimeInstallDir, pkgInstallDir, packagesFilePath)
	default:
		return fmt.Errorf("download: packages_file install not yet supported for runtime %q", rt.Type)
	}
}
```

`installNodePackagesFile(runtimeInstallDir, pkgInstallDir, packagesFilePath string) error`: same
scratch-dir-then-`finalizeInstall` shape as `installNodePackage`, but copies `packagesFilePath`
into the scratch dir as `package.json` first (so a bare `npm install` — no package arg — reads it
from cwd) and sets `cmd.Dir` to the scratch dir instead of relying on `--prefix` alone:

```go
func installNodePackagesFile(runtimeInstallDir, pkgInstallDir, packagesFilePath string) error {
	npm := filepath.Join(runtimeInstallDir, "bin", "npm")
	if _, err := os.Stat(npm); err != nil {
		return fmt.Errorf("download: npm not found at %s: %w", npm, err)
	}
	if err := os.MkdirAll(filepath.Dir(pkgInstallDir), 0o755); err != nil {
		return err
	}
	tmpDir, err := os.MkdirTemp(filepath.Dir(pkgInstallDir), ".tmp-*")
	if err != nil {
		return err
	}
	defer os.RemoveAll(tmpDir)

	data, err := os.ReadFile(packagesFilePath)
	if err != nil {
		return err
	}
	if err := os.WriteFile(filepath.Join(tmpDir, "package.json"), data, 0o644); err != nil {
		return err
	}

	cmd := exec.Command(npm, "install")
	cmd.Dir = tmpDir
	cmd.Env = append(os.Environ(), "PATH="+filepath.Join(runtimeInstallDir, "bin")+string(os.PathListSeparator)+os.Getenv("PATH"))
	out, err := cmd.CombinedOutput()
	if err != nil {
		return fmt.Errorf("download: npm install (packages_file %s): %w: %s", packagesFilePath, err, out)
	}
	return finalizeInstall(tmpDir, pkgInstallDir)
}
```

The resulting shim/bin dir for PATH purposes is `filepath.Join(pkgInstallDir, "node_modules",
".bin")`.

## New package: `pkg/trunk/actions`

A dedicated package, not an extension of the (already 40KB) lint `engine` package — actions are
single Run invocations with hook/CLI context, not file-matched batch jobs; the two execution
models don't share enough to justify coupling them, and this mirrors how `download` and `engine`
are already separate packages for separate concerns.

### `Resolve`

```go
// Resolve returns cfg's enabled actions, optionally restricted to only those with a
// git_hooks trigger naming hookName.
func Resolve(cfg config.Config, hookName string) []config.Action
```

Iterates `cfg.Actions.Definitions` filtered to ids in `cfg.Actions.Enabled` (already trimmed by
`filterEnabled`, so in practice this is just "all of `cfg.Actions.Definitions`" today — the
`hookName` param does the real work), sorted by `ID` for deterministic execution order. When
`hookName == ""`, returns every enabled action (for `rtunk actions list`). When non-empty, keeps
only actions with a `Trigger.GitHooks` entry containing `hookName`.

### `Run`

```go
// RunOptions carries everything Run needs beyond the action/config itself.
type RunOptions struct {
	CacheDir string   // "" -> OS default, same convention as pkg/trunk/download
	Hook     string   // git hook name for ${hook}; "" for a manual `rtunk actions run <id>`
	Args     []string // positional args forwarded from the git hook's own argv; ${1}.., ${@}
	Stdin    io.Reader // hook's stdin, read lazily only if ${hook_stdin_path} appears in Run
}

// Result is one action run's outcome, and also the shape persisted to history.
type Result struct {
	ActionID string
	Hook     string
	StartedAt time.Time
	Duration  time.Duration
	ExitCode  int
	Skipped   bool   // true when interactive:true skipped a non-interactive context
	Err       string // non-empty on a launch failure (before the process even started)
}

func Run(ctx context.Context, cfg config.Config, action config.Action, opts RunOptions, stdout, stderr io.Writer) (Result, error)
```

Steps, in order:

1. **Interactive gate.** If `action.Interactive == "true"` and `os.Stdin` is not a character
   device (`term.IsTerminal`-equivalent check via `os.Stdin.Stat()`'s `os.ModeCharDevice` bit —
   the stdlib idiom, no new dependency), return `Result{Skipped: true}` immediately, no process
   ever launched.
2. **Resolve runtime shim dir**, if `action.Runtime != ""` — reuses
   `download.ResolveVersion`/`download.InstallDir`/`download.ShimPath`/`download.Download`
   exactly as `engine.resolveRuntimeShimDir` already does (that function is
   `engine`-package-private; this package gets its own copy — same ~15 lines, not worth exporting
   across a package boundary for one call site each).
3. **Resolve `PackagesFile`**, if set — content-hash `action.PackagesFile`'s bytes (sha256, hex),
   `installDir := download.InstallDir(root, "action-packages", action.ID, hash)`; if not already
   present, run `download.InstallPackagesFile(rt, runtimeInstallDir, installDir, packagesFilePath)`.
   Add `filepath.Join(installDir, "node_modules", ".bin")` to the front of the exec PATH (node
   only, per Non-goals — a non-node runtime with `PackagesFile` set is a config error surfaced by
   `InstallPackagesFile`'s own explicit error).
4. **Substitute template vars** into `action.Run`: `${cwd}` (quoted `action.SourceRoot` joined with
   `action.SourceDir`, exactly like `Linter`'s own resolution), `${plugin}` (quoted
   `action.SourceRoot`), `${hook}` (bare `opts.Hook`, unquoted — real trunk-announce passes it
   quoted itself: `"${hook}"`), `${1}`..`${9}` (bare `opts.Args[i-1]`, empty string if out of
   range), `${@}` (space-joined, individually-quoted `opts.Args`, same `quoteAll`/`quoteOne` shape
   `engine` already uses — small local copy, same reasoning as step 2), `${hook_stdin_path}`
   (drains `opts.Stdin` into a `os.CreateTemp` file the first time it's needed, removed via
   `defer`; empty/no-op if `opts.Stdin == nil}`), `${env.NAME}` (regex `\$\{env\.([^}]+)\}`,
   `os.Getenv` substitution — same behavior as `download.resolvePlaceholders`, small local copy for
   the same reason as steps 2/`${@}`). An unrecognized `${...}` var is a hard error before exec
   (mirrors `engine.findUnsupportedVar`'s allowlist-guard pattern) — catches a typo'd or
   not-yet-supported var instead of literally passing `${something}` to the shell.
5. **Exec** via `sh -c`, `cmd.Dir = action.SourceRoot` joined with `action.SourceDir` (an action
   with no `SourceDir`/`SourceRoot` — i.e. defined in the repo's own local plugin source with no
   nested dir, or none at all — runs from the invoking process's own cwd, matching how a Linter
   with empty `SourceDir` already behaves), `cmd.Env` = `os.Environ()` + PATH-prepended (runtime
   shim dir, then packages_file bin dir if any) + `download.BuildEnv(action.Environment, nil)`
   appended last (so an explicit `Action.Environment` entry can override the ambient environment,
   matching normal `os.Environ()`-then-append shadowing semantics already used everywhere else in
   this codebase), `cmd.Stdout`/`cmd.Stderr` = the caller's `stdout`/`stderr` directly (unlike
   `engine`, actions have no findings/output-parsing to capture — the action's own output _is_ the
   product, streamed straight through, matching how a real git hook's output reaches the
   terminal), `cmd.Stdin` = `os.Stdin` (so an action's own script can still read stdin directly if
   it wants to, independent of `${hook_stdin_path}`).
6. **On non-zero exit and `action.NotifyOnError` (default true, per Non-goals):** best-effort
   native notification, error ignored.
7. **Append to history** (see below) and return `Result`.

### History

```go
// Append records one action run to cfg's history log (bounded to the most recent 200 entries,
// oldest dropped -- an unbounded audit log for a local dev tool is the wrong default; 200 covers
// weeks of normal use and keeps the file trivially small).
func AppendHistory(cacheDir, repoRoot string, r Result) error

// History returns cfg's history log, most recent first, optionally filtered to one action id
// ("" for all) and capped at limit (0 for no cap beyond the 200 the log itself already bounds to).
func History(cacheDir, repoRoot, actionID string, limit int) ([]Result, error)
```

Stored as JSON Lines at `<cacheDir>/actions-history/<sha256(repoRoot)>.jsonl` — keyed by repo root
the same way `pkg/trunk/config/cache.go`'s `sourceHash` keys a plugin source, since `.rtunk/` (the
natural repo-local home) doesn't exist yet (`internal/cli/findtrunk.go`: "rtunk's own
`.rtunk/rtunk.yaml` is not read yet") and history is inherently per-repo, not global — the shared
cache dir is the only persistent-state location that exists today. `AppendHistory` reads the whole
file, appends, truncates to the newest 200, rewrites atomically (temp file + rename, same pattern
as `config/cache.go`'s `saveSourceCache`) — simplest correct approach for a file this small; no
need for true append-only I/O at this scale.

### Notification helper

```go
// notify is a best-effort native notification -- failures are silently swallowed, since a
// notification that can't be shown must never fail the action run that triggered it.
func notify(title, body string) {
	switch runtime.GOOS {
	case "darwin":
		script := fmt.Sprintf("display notification %q with title %q", body, title)
		_ = exec.Command("osascript", "-e", script).Run()
	case "linux":
		if path, err := exec.LookPath("notify-send"); err == nil {
			_ = exec.Command(path, title, body).Run()
		}
	}
}
```

## New package: `pkg/trunk/githooks`

```go
// Install writes a shim script into each git hook name referenced by any of cfg's currently
// enabled actions' git_hooks triggers, so git itself invokes rtunk at the right lifecycle points.
// hooksDir is where git actually looks (see hooksDir below) -- never assumed to be .git/hooks,
// since `git config core.hooksPath` can move it (trunk itself respects this; AGENTS.md's
// "config-compatible where practical" extends to this behavior). An existing hook file at a target
// path that isn't rtunk's own (missing the marker comment) is left untouched and reported as
// skipped unless force is true -- never silently overwritten (a repo may already use husky,
// pre-commit, or a hand-written hook).
func Install(repoRoot string, cfg config.Config, force bool) (installed, skipped []string, err error)

// Uninstall removes every hook file under hooksDir that carries rtunk's marker comment. A
// foreign (non-rtunk) hook is left untouched, same as Install's own skip logic.
func Uninstall(repoRoot string) (removed []string, err error)

// hooksDir returns where git hooks actually live for repoRoot: `git config core.hooksPath` if
// set (resolved relative to repoRoot if relative, per git's own documented behavior), else
// "<repoRoot>/.git/hooks".
func hooksDir(repoRoot string) (string, error)
```

The installed shim (`0o755`, one per referenced hook name):

```sh
#!/bin/sh
# Installed by rtunk git-hooks install -- do not edit by hand. Run `rtunk git-hooks uninstall`
# to remove.
exec rtunk actions run --hook <hookname> -- "$@"
```

The marker comment (`# Installed by rtunk git-hooks install`) is how `Install` (re-run without
`--force`) and `Uninstall` both recognize a hook file as rtunk's own versus a foreign one — a
simple, greppable string check on the file's first two lines, not a checksum or metadata file.

`Install` computes the hook-name set by calling `actions.Resolve(cfg, "")` (every enabled action)
and collecting every distinct `Trigger.GitHooks` entry across all of them — no fixed hook-name
whitelist; whatever `git_hooks` values the enabled actions' plugin.yaml files declare is exactly
the set installed, so `git-hooks install` stays correct as the enabled action set changes without
rtunk needing its own enumeration of "every git hook that exists."

## CLI (`internal/cli`)

### `actions.go`

```go
type actionsCmd struct {
	List    actionsListCmd    `cmd:"" default:"withargs" help:"List actions available for the current configuration."`
	Enable  actionsEnableCmd  `cmd:"" help:"Enable one or more actions."`
	Disable actionsDisableCmd `cmd:"" help:"Disable one or more actions."`
	Run     actionsRunCmd     `cmd:"" help:"Run an action on demand, or every action a git hook triggers."`
	History actionsHistoryCmd `cmd:"" help:"Show recent action runs."`
}
```

- **`actionsListCmd`** (`[--enabled]`): same shape as `checkListCmd` — every `cfg.Actions.Definitions`
  id (via `ResolveAll` when `--enabled` is absent, `Resolve` when present — matching
  `check list`'s own existing `--enabled` semantics exactly), one per line, an `(enabled)` suffix
  when its id is in `cfg.Actions.Enabled`.
- **`actionsEnableCmd`**/**`actionsDisableCmd`** (`ID []string`): generalizes `editEnabled` (renamed
  `editList`, taking a `listKey string` — `"enabled"` or `"disabled"` — instead of a hardcoded
  `"enabled"`; `checkEnableCmd`/`checkDisableCmd` become one-line callers of
  `editList(cli, "lint", "enabled", ...)`, unchanged behavior). Enable: `addEnabled` onto
  `actions.enabled`, `removeEnabled` onto `actions.disabled`, one file write covering both edits
  (open the YAML doc once, mutate both sequence nodes, encode once — not two separate
  read-modify-write round trips). Disable: the mirror.
- **`actionsRunCmd`**: either `ID string` (positional, `arg:"" optional:""`, manual single-action
  run) or `Hook string` (`--hook`, runs every action `actions.Resolve(cfg, hook)` returns, in
  order, stopping at the first non-zero exit and propagating its exit code — matching standard
  git-hook chaining semantics). `Run()` validates manually that exactly one of `ID`/`Hook` is
  non-empty (a positional arg and a flag aren't a clean fit for Kong's `xor:""` tag group, which is
  designed for same-kind fields) and returns a clear usage error otherwise. `Args []string` (passthrough,
  same `passthrough:""` pattern `execCmd.Args` already uses) forwards positional args (`${1}..`,
  `${@}`); reads `os.Stdin` lazily only if any matched action's `Run` references
  `${hook_stdin_path}` (checked via `strings.Contains` before wiring `opts.Stdin`, so a hook
  invocation that never needs stdin never blocks trying to read it).
- **`actionsHistoryCmd`** (`[--id <action-id>] [--limit N, default 20]`): prints
  `actions.History(...)` one line per run — timestamp, action id, hook (or "manual"), exit code /
  "skipped", duration.

### `githooks.go`

```go
type gitHooksCmd struct {
	Install   gitHooksInstallCmd   `cmd:"" help:"Install git hooks for enabled actions."`
	Uninstall gitHooksUninstallCmd `cmd:"" help:"Remove rtunk-installed git hooks."`
}
```

- **`gitHooksInstallCmd`** (`[--force]`): resolves the repo root (`git rev-parse --show-toplevel`,
  same call `findTrunkYAML` already makes), calls `githooks.Install`, reports installed/skipped
  hook names.
- **`gitHooksUninstallCmd`**: calls `githooks.Uninstall`, reports removed hook names.

### `cli.go`

Registers `ActionsCmd actionsCmd` and `GitHooksCmd gitHooksCmd` alongside the existing commands.

## Template variable contract (Action.Run / Action.Environment values)

| Var                  | Resolves to                                      | Notes                                                     |
| -------------------- | ------------------------------------------------ | --------------------------------------------------------- |
| `${cwd}`             | `SourceRoot` joined with `SourceDir`, quoted     | mirrors `Linter` exactly                                  |
| `${plugin}`          | `SourceRoot`, quoted                             | mirrors `Linter` exactly                                  |
| `${hook}`            | the git hook name, bare                          | `""` for a manual run                                     |
| `${1}`..`${9}`       | `opts.Args[i-1]`, bare                           | empty string if out of range                              |
| `${@}`               | `opts.Args`, individually quoted, space-joined   |                                                           |
| `${hook_stdin_path}` | path to a temp file holding `opts.Stdin`'s bytes | lazy; only drained if referenced                          |
| `${env.NAME}`        | `os.Getenv("NAME")`                              | matches `download.resolvePlaceholders`' existing behavior |

Any other `${...}` is a hard error before exec (typo/unsupported-var guard, matching
`engine.findUnsupportedVar`).

## Testing strategy

- **Config layer:** table tests for `Action.Environment`/`SourceDir`/`SourceRoot` parsing
  (mirroring existing `Linter` tests), `CategoryConfig.Disabled` round-trip, cache-schema-version
  bump regression test (same shape as the three prior ones this session).
- **`download.InstallPackagesFile`:** a real end-to-end test against the actual cached node runtime
  on this machine (same pattern `download_test.go` already uses for real npm/pip installs) —
  install a tiny fixture `package.json` (one real, tiny, pinned npm package), assert its bin ends
  up in `node_modules/.bin`.
- **`actions.Run`:** unit tests per template var (each substituted correctly, unsupported var
  rejected), an interactive-skip test (fake non-tty stdin), a `PackagesFile`-driven end-to-end test
  using the same real node runtime, a `NotifyOnError` test asserting the exec attempt happens (not
  asserting an actual OS notification appears — CI/sandboxed environments may have neither
  `osascript` nor `notify-send`).
- **`actions.History`:** append/read round-trip, 200-entry bound enforced.
- **`githooks.Install`/`Uninstall`:** real temp git repo (`git init`), assert shim content, marker
  detection, `core.hooksPath` respected, foreign-hook-not-overwritten-without-`--force`.
- **CLI:** table tests mirroring `check_enable_test.go`/`check_run_test.go`'s existing shape for
  `actions enable/disable/list/run/history`, `git-hooks install/uninstall`.

## Rulings (for final disclosure)

1. `schedule:`/`files:` triggers are parsed but never auto-fire (daemon-dependent, permanently out
   of scope per AGENTS.md).
2. `PackagesFile` install support is node-only (the only real catalog action needing it, exactly
   like `InstallPackage`'s own existing per-type dispatch).
3. `actions.disabled:` is a purely advisory, CLI-managed sibling of `actions.enabled:` with no
   resolution-time effect — a ruling grounded in this repo's own real `trunk`-CLI-edited file, not
   a confirmed trunk-internal spec.
4. `NotifyOnError`'s unstated default is `true` (every real example that sets it explicitly sets it
   `false`, implying suppression is the non-default case).
5. `interactive: true` skips outside a TTY context; `optional`/unset always run — grounded in the
   real `trunk-check-pre-push` / `trunk-check-pre-push-always` sibling-action comment.
6. Action run history lives under the shared cache dir (keyed by repo-root hash), not `.rtunk/`,
   since `.rtunk/` doesn't exist until v0.7's `rtunk init`.
7. `rtunk git-hooks install` computes the hook-name set dynamically from enabled actions' own
   triggers rather than installing a fixed, exhaustive list of every git hook name that exists.
